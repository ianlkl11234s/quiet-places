# GPU 水面波動：第一階段

## 已實作的範圍

`src/systems/WaterSimulation.ts` 以 GPU ping-pong render targets 保存高度 h（m）與垂直速度 v（m/s）。每次固定步長解：

```text
v ← v + dt × (c² ∇²h − β ∇⁴h − damping × v + pressure)
h ← h + dt × v
```

這是固定 3.6 m 方形域的 **線性阻尼色散波動方程／高度場模型**，不是完整 Navier–Stokes、SPH、三維水體、空氣流動或魚與水的流固耦合。模擬可以描述小幅波紋的傳播、反射與衰減；不能描述翻浪、飛濺、水量搬運或水面拓撲改變。

- WebGL 2 + EXT_color_buffer_float；128×128、RGBA HalfFloat，線性 texture filtering。
- dt=1/120 s、c=0.55 m/s、dx=3.6/128 m，CFL 約 0.163；β=10⁻⁶ m⁴/s²，以四階項區分不同波長的傳播；每幀最多 6 步，背景恢復不無限補算。
- 近鄰 Laplacian 與 13 點雙 Laplacian、鏡射 ghost samples 的 Neumann 邊界、邊界額外阻尼；初始為毫米尺度非規則波面。
- 小幅平衡壓力模式持續激發波面；輕點天窗注入中央 −3 mm、周邊補償的 Mexican-hat 高度擾動（σ 約 6.5 cm）。這是受迫波，不是自行生長的海浪。
- GPU 當前高度 texture 同時供 vertex displacement、法線與折射讀取。天空依折射射線取樣同一程序式天空函式，並有 Fresnel 反射近似。
- 牆地焦散使用模擬坡度扭曲取樣，但亮度聚焦仍為程序式近似；體積光保持已接受的實作與 0–250% 控制。

## 操作與失敗

- 輕點天窗產生漣漪；拖曳仍為 90° 環繞，位移超過 5 px 的拖曳不注入擾動。
- 「重設水面」恢復確定性的初始波面；暫停時不推進 solver。
- GPU float render target 不可用時，設定面板明確顯示程序式 fallback，關閉模擬專用重設與輕點提示。
- 非數值 dt／座標不進入 solver；初始化失敗清理已分配資源。更新保存並還原 renderer render target、viewport、scissor 與 autoClear。

## 實際驗收

本機 Vite 開啟 `/tests/water-gpu.html` 執行真正 GPU 計算與 half-float readback，不使用 CPU 假資料。診斷只在 smoke 中讀回，正常動畫沒有每幀 GPU→CPU 同步。

2026-09-06 實際讀回：

| 檢查 | 結果 |
|---|---|
| 初始最大高度 | 0.0031395 m |
| 單次擾動後最大速度 | 0.0020714 m/s |
| 7,201 次固定更新後最大高度／速度 | 0.0006762 m／0.0008497 m/s |
| 數值有限、dt=0 不變、reset 等於初始 | 通過 |
| 1×1/60 與 2×1/120 更新結果一致 | 通過 |
| renderer target／viewport／scissor 還原 | 通過 |

`stateNorm` 僅為診斷狀態範數，不是具物理單位的流體能量。上述約 60 秒模擬時間，不代表實體手機長時間耗電／發熱驗收。

主頁設定顯示 GPU 模式，天窗輕點與既有光束實看；production build 通過。尚未做不支援 GPU 的實機、不同瀏覽器驅動或長時間耐久測試。

## 漣漪修正

使用者指出原擾動像彈性水膜：把寬廣單向速度脈衝改為局部下凹與補償環，縮小背景波幅並降低風壓。加入弱色散，避免所有波長具有同一波速；以鏡射樣本處理邊界，擾動中心離邊至少 0.234 m，減少補償環被截斷。零體積是連續平面理論，離散與阻尼仍有誤差，不宣稱嚴格質量守恆。新版再通過 7,201 更新與 reset／固定步長／renderer state 檢查；細波視覺辨識度仍需使用者確認。

## 持續水波與漣漪並存

恢復多尺度程序式風波作為底層，疊加 GPU 高度。渲染將 GPU 高度放大 3 倍以提高漣漪辨識度，幾何與法線採同一混合高度；solver 數值與步長未變。恢復坡度控制的細反光，保留天空折射層。這是藝術化混合模型，不宣稱畫面位移全為物理真值。
