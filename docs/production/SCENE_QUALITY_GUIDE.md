# 場景品質準則（新場景與大改適用）

更新：2026-09-26。來源：[畫面精緻度評估](VISUAL_QUALITY_PLAN.md)中，9 景反覆出現的缺口。

[MASTER](../prompts/quiet-places-master.txt) 決定「要什麼樣的畫面」；本頁決定「怎樣算做到位」。兩者衝突時，以 MASTER、使用者明確指示和已確認基準為準。

文中數值都是**建議起點**，每個場景需要自己校準，不是自動驗收門檻。

## 1. 光

- **主光要說得出來源**：天窗、窗、開口、水面反射，或月光。畫面外的光也要能指認方向。
- **暗可以，但暗要有原因**：
  - 受光區周圍要有一點合理的反彈光：地面把光反到牆下緣、窗邊側牆被照到一點。
  - 暗部裡的主體（牆角、扶手、生物）要讀得出形體。
  - 不可以用均勻 ambient 或整體提高曝光來處理。
- **每個時段都要能分辨，至少同時在三項上有差異**：光的角度、色溫、強度、天空／窗景色。
  - 晨曦：低角度、偏暖、陰影長，和正午明確分開。
  - 暮色：暖色而且更斜。天空不能是中性灰。
  - 月夜：必須要有一個說得出來源的光（月光斑、窗外路燈、店燈）。不能是全黑，也不能是「白天壓暗」。
- **窗景、天空和室內光由同一個時刻驅動**：沿用 `sampleTime`。檢查窗外的天空和樹葉在月夜是否真的變成夜景。
- **Bloom** 只用在真正高亮的來源上。鰭、葉邊、雪面不可以出現光暈白邊。

## 2. 材質與貼圖

- 表面不能只是純色平面：至少要有 roughness 變化，或細微的 normal。近景主體要有 PBR 貼圖組。
- 貼圖預算（沿用 stairlight 的規則）：
  - 主要表面 2K。
  - 只有近景能證明需要時才升 4K。
  - 次要與遠景表面用 512²–1K；第一眼會看到的鏽斑、髒污不低於 1K。
- **遠景不能留灰盒**：至少要有基本的色彩與窗、門分割。
- **環境反射與 AO**：
  - 有 Blender 烘焙的場景，同時烘 AO 或 lightMap。
  - 沒有烘焙的場景，用弱 PMREM 天空環境，強度設上限，不抬黑位。
- **擬真細節**：裂縫、污漬要有凹凸或粗糙度差異，不可以只畫一條黑線。濕的表面、金屬、雪各自要有正確的反射特性。

## 3. 幾何與畫質

- **接觸處**：物體接地、接牆的地方要有接觸陰影或 AO，不能看起來像浮著。
- **剪影**：主要輪廓和生物在正式視距下不能看得出面數。鰭、葉要有厚度，或邊緣透光。
- **抗鋸齒**：
  - 經過 EffectComposer 的畫面，MSAA 由 `src/player/RenderPipeline.ts` 的 `SceneRenderPass` 負責：只有畫場景那一步做多重取樣，後處理的畫布是單取樣。只設 `antialias:true` 沒有效果，畫布本身已經改成 false。
  - MSAA 在 Apple／Chrome 上的成本大約和取樣數成正比，而且集中在特定物件；SMAA 會讓比像素還細的細節斷裂。調查與數據見 `exports/render-perf/README.md`。
  - 驗收時放大檢查細欄杆、遠方小魚、倒影邊緣。
- **反射與倒影**：擾動要隨距離和掠射角衰減，不可以出現塊狀黑斑。

## 4. 生物

「看起來像活的」拆成四層逐一檢查：

| 層 | 要求 |
|---|---|
| 模型 | 側面和上方輪廓都和參考照片比對過（鼻端、眼、鰭位置、尾長比例）；鰭有厚度或透光薄邊；眼睛不是另外貼上去的小球 |
| 材質 | 背深腹淺；以視角決定的鱗片或皮膚光澤；鰭用 alpha 漸層；逆光下靠輪廓光或透光保留形體，不是全黑剪影；也不能變成發光體（MASTER 禁止 glowing） |
| 動作 | 擺尾或拍鰭的頻率跟游速連動，用游過的距離或速度積分相位，**不能用 elapsed 固定時鐘**；轉向時產生側傾和身體彎曲；低速懸停時尾巴靜止、改用胸鰭；俯仰要有限制，不能出現垂直姿勢 |
| 行為 | 用的是物種的典型動作（不要無緣無故翻滾）；每隻有速度、相位、大小的差異；路線不擋鏡頭、不長時間貼著鏡頭；喜歡出現在光暗交界；群體有間距，不能同步 |

- **可辨識度**：主角在正式視距下，要讀得出物種特徵（輪廓、配色）。只有十幾個像素、看不出是魚時，就調整路線或尺度，不要把它加亮。
- **優先沿用共用模組**：`src/shared/biology/` 的本體，以及運動、材質的共用層（建立後見[能力索引](CAPABILITIES.md)）。不要在場景裡重寫補光和轉向邏輯。
- 物種的事實和美術近似分開記錄在 `docs/biology/<物種>.md`。

## 5. 效能預算（初始，待實測）

- 可見模型約 5–12 萬 triangles。
- 單一主投影光，shadow map 2048；低畫質先試 1024。
- 單一場景 GLB 以 25 MB 內為目標。超過時先檢查貼圖解析度是否符合第 2 節的預算。
- 記錄 frame interval、draw calls、DPR、資產大小。MSAA、shadow、貼圖改動前後都要量。
