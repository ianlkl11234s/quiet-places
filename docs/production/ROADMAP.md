# 長期專案實作總計畫

更新：2026-09-09。本文是後續執行與驗收的權威計畫，取代先前簡短候選表；原交接草稿保留本地技術背景，實作不依賴該未追蹤文件。使用者已授權實作至 P6。2026-09-09 已完成本地 pilot 實作與下列技術驗收；[P0–P6 交付紀錄](P0_P6_ACCEPTANCE.md) 是目前證據入口。P5 開口正式採用仍有人工烘焙交接，P7／P8 未啟動。

## 最終目標與完成定義

Quiet Places 可以持續製作房間：保留共同風格，沿用已有模型、材質／光水能力及製作方法，以實驗累積使用者偏好，且能追溯、重現與回退。網站是目前宿主；未來 app 與製作工具使用同一套場景能力。

整體完成須同時具備：

1. 四個既有房間的構圖、光影、動態、操作維持已記錄基準；任何美術差異另列並由使用者確認。
2. 一個新增房間完成端到端製作，實際沿用至少一種既有生物與一項光／水／空間能力，沒有複製第二份核心實作。
3. 太陽／開口、游動路徑與聲音工具可以預覽、保存候選、重新載入、比較與採用；採用有紀錄並可回退。
4. 資產由來源、工具、設定、輸出到 runtime 的關係可查；指定 pilot 能在新輸出目錄重建，不能只靠作者目前開著的 Blender。
5. 新 session 只讀 repo 入口及相關資料，就能完成一項真實修改；不需要私人聊天歷史。
6. app 階段在選定目標平台完成封裝及實機驗收。網站完成與 app 完成分開報告；商店發布另列。

「減少重新探索」的證據：P0 記錄一項既有修改需要尋找的入口、重複填值點及重現缺口，P7 再比較；報告實際沿用清單、新研究事項、人工同步點和耗時（若可取得）。不預先承諾省下固定百分比。

## P0：保護基準與建立可比較驗收

**範圍**：Git／worktree、四個場景、現有 tests、assets／public／exports 分類。

1. 建立本輪檔案清單，區分原有未提交、本輪文件、來源、生成結果與歷史證據；核對分支及遠端資訊，禁止廣泛 staging 或清理。
2. 以明確提交或含 patch／未追蹤輸入 hash 的快照固定基準；如需 worktree，明確搬入本輪依賴，不丟掉 dirty 文件。提交僅包含本輪已驗收責任範圍。
3. 記錄四場景代表性桌面／直式畫面：日間、暮色／夜間、適用天氣及水位、暫停、切換／失敗恢復、dispose。固定 camera、viewport、時間、曝光、品質、seed／elapsed、資產版本。
4. 先沿用 GPU HTML／TS 測試；確認兩個測試確有相同責任後才抽共用記錄器。保留各場景特有斷言。
5. 保存 frame interval 分布、資源數與載入情況的現況；在變更前寫下可接受差異／效能門檻，不能看結果後放寬。美術比較保留受光、暗部、主角與開口局部圖。

**交付**：`exports/<review-id>/` 基準畫面、環境與結果 JSON；`docs/VALIDATION.md` 摘要及資產分类清單。敏感資訊不入快照。

**完成條件**：四場景均有可回看固定條件；可執行 tests／build；缺少 browser 或硬體時標受阻，不以歷史畫面代替。

**回退**：此階段只建立證據，不修改外觀；原檔保留。

## P1：幾何單一參數來源

**入口**：`src/places/afterlight/DrainOpening.ts`、`assets/blender/scripts/update_afterlight_drain.py`、相關 GLB／metadata、`tests/afterlight-drain.test.ts`。

1. 逐一列出 TS／Python／模型目前重複的尺寸、原點、軸向、鏡射與框條計算；確認 loader 和 TypeScript JSON 支援。
2. 建立一份有版本、單位與座標約定的設定。以目前值遷移，派生尺寸從設定計算，不把派生值另抄回三份文件。具體檔名在此步定案並更新能力索引。
3. runtime 與 Blender 同讀；雨路、光路遮罩、框條及洞口同步。拒絕非有限值、負尺寸、無效框寬和未知版本。
4. 在副本／新輸出目錄重建，核對實際 GLB bounds、節點、孔洞及鏡射；連續執行不重複拉伸。確認 indirect bake 受影響範圍。

**交付／完成**：同值遷移通過實際產物與固定畫面比較；一個受控尺寸候選證明所有消費者跟隨同一設定，之後恢復正式基準。不得只比較 metadata。

**回退**：設定、兩端 consumer 與相關產物視為相容單位一起退回；原 blend 不覆寫。

## P2：資產製作 recipe 與來源追蹤

**pilot**：Afterlight 建築／格柵及 Medaka 生物管線；沿用 `medaka/build_all.py`，不先另造整套 runner。

1. 分開來源資產、recipe、生成輸出、runtime 產物與 review。記錄工具版本、必要硬體／外掛、工作目錄、輸入及明確命令。
2. 共用機制限於 preflight、步驟執行、失敗停止、log、hash 與 manifest；物件名、日照、材質、烘焙設定由 recipe 擁有。
3. manifest 記 asset ID／版本、來源／作者／授權狀態、輸入 hash、設定版本、工具版本、輸出 hash、單位／軸向、模型／clip 契約、消費者及驗收。未知授權保持未知。
4. 輸出先寫暫存／版本目錄；驗證通過才提升到 runtime 路徑。失敗不得留下看似成功的部分 public 更新；保留上一版。
5. 建立改動對應步驟表：runtime-only、材質、拓樸／UV、rig／motion、開口／GI。讓操作者知道何時須重烘焙。

**完成條件**：兩條實際 recipe 在乾淨輸出目錄成功重建並回讀；錯誤輸入會停止；輸出 hash 可核對；非確定性烘焙用事前設定的容差與畫面驗收，不要求二進位完全相同。

**回退**：recipe 與產物版本成對保留；不清除原始來源與歷史 bake。

## P3：可重用能力與知識補齊

**入口**：`src/shared/`、各場景生物 adapter／motion、`docs/biology/`、光水製作頁。

1. 以 Medaka 為第一個生物重用 pilot：分離模型載入／clip 或 cache 取樣等本體責任，場景保留路徑、邊界、數量、受光與尺度。先在第二個隔離試片消費，正式房間不換魚。
2. 為現有生物補契約：前向軸、單位、rig／clip、時間、頻率／速度公式入口、cache 版本、資源 ownership；事實、美術假設與未知分開。
3. 核對水光／海光 shared optics 的可重用範圍；記錄透明排序、吸收、反射、折射、套件版本與近似。光照記 direct／indirect、曝光、散射、遮擋、反光與 bake 邊界。
4. 選一項有第二個消費者的空間 helper（如矩形開口／框）抽取；若責任不同，記錄不抽的原因。植物阻尼、雨與生物行為不因公式相似硬合併。
5. 每項共用 API 記输入／輸出、單位、所有權、失敗方式、消費者、最小用例及測試。

**完成條件**：至少一個生物本體與一項環境能力有兩個真實可執行消費者；檢查 finite values、暫停、dispose、seed 序列和視覺差異。不得以未使用 helper 算共用完成。

**回退**：先保留原 adapter 介面，逐消費者遷移；同批不改物種或美術值。

## P4：播放器、場景註冊與宿主邊界

**入口**：`src/main.ts`、`src/places/metadata.ts`／`catalog.ts`、`src/player/contracts.ts`、`src/systems/Preferences.ts`。

1. 盤點 main 的場景 ID 分支、控制項、相機／天氣能力。先把現有能力放回既有 registry／contract，不建立競爭 registry。
2. 由能力產生已有控制項，保留 URL ID、深色圓鈕、鍵盤／焦點、鏡頭操作與偏好遷移。明確禁止未知能力套到其他房間。
3. 只將 app／工具確需重用的生命週期從 DOM host 分離：時間、載入、切換、暫停與 dispose；不提前把所有 UI 抽象化。

**完成條件**：四場景切換、暫停、失敗恢復、偏好还原、桌面／直式與資源释放回歸通過；保留舊版 preference 遷移案例。

**回退**：每批遷移一類控制；舊設定讀取相容，避免不可逆寫入新格式。

## P5：製作實驗工具

工具入口與一般觀賞 UI 分開；共享正式場景工廠、shader、motion 與時間。先固定一項工具的預覽、紀錄與採用步驟，再擴下一項；依使用者2026-09-09確認，允許人工交接，不要求全自動閉環。

**共同 preset 契約**：schemaVersion、sceneId、基準版本、資產版本、參數與單位、相機、viewport、時刻／天氣、品質、seed／elapsed。拒絕未知版本、錯場景、非有限值與超範圍值；提供預覽、重設、匯出／匯入和比較。採用才回寫正式權威設定，保留前版與實驗決策。LocalStorage 不是唯一紀錄。

| 批次 | 功能 | 驗收 |
| --- | --- | --- |
| P5a 太陽／光 | 用 Afterlight 預覽方向、強度、曝光及已支援散射；清楚標記美術日照模型 | 匯出後重新開啟可重現；同條件 A/B；不暗中更換 GI |
| P5b 空間開口 | 調位置、寬高／深度，使用 P1 契約 | 動態預覽標草稿；需更新 GLB／重烘焙時顯示過期狀態；正式採用經 P2 重建後比較 |
| P5c 生物路徑 | 編輯 pilot 路徑控制點、速度／節奏，呼叫正式 motion | 連續姿態、曲率／速度、邊界、暫停、seed；未知生物參數不通用化 |
| P5d 聲音 | 沿用 MusicPlayer／AudioSystem 試聽、音量、loop／淡入淡出及搭配房間 | 預設靜音、主動啟動、切換／背景行為、授權顯示；無第二套播放器 |

**完成條件**：每種工具至少保存一次真實比較與採用／拒絕理由；preset 重新匯入重現，錯誤版本有明確訊息；取消不污染正式設定。使用者美術選擇列為待確認，不由 agent 自行宣稱喜歡。

**回退**：工具可獨立停用；採用操作可恢復前版設定及配對資產。

## P6：harness 與累積機制實際驗證

1. 對照本輪真正流程縮修 AGENTS／skill，不再增加重複規則。檢查 skill 可發現／載入與實際觸發分開；需要時才調整 repo 安裝位置，不冒充已啟用 hooks。
2. 把本輪真實經驗寫回相關場景、生物與偏好頁，採用／拒絕都有來源；舊歷史按需加目前摘要，不全文搬家。
3. 將 check:project 擴成有價值的契約檢查：正式場景文件／入口、recipe／manifest 引用、已宣稱產物的 hash、preset 版本。未知狀態不強迫填假值。
4. 做一次隔離接手演練：另一個有界 agent／新 session 僅取得 repo 與任務，完成「重現試片、改一個候選、保存實驗、更新文件」，主 agent 核對產物與假設。

**完成條件**：演練不依賴聊天補充即可找到入口、重現及回退；記錄實際遇到的缺口並修正。skill 格式檢查只算格式，不算行為驗證。

## P7：新房間驗證最終目標

使用者選定新房間參考與主角；未選前可用隔離灰模驗證技術，但不把灰模宣稱正式房間。現有 stairlight 草稿不代表已選定製作。

1. 用 brief 記共同風格、本次偏好及例外，列出沿用／調適／新研究清單。
2. 依 P2 recipe 製作空間，P3 接入已有生物及環境能力，P5 比較太陽／開口、動態與聲音；保存實驗及使用者選擇。
3. 經 P4 註冊；驗四景未退步與第五景生命周期、畫面、資產及降級行為。
4. 對照 P0 的查找／同步缺口，交付哪些能力真正減少重做、哪些仍需研究；修正無效抽象。

**完成條件**：新房間可由 recipe／設定重現；至少一個已有生物與一項環境能力實際沿用；技術驗收及使用者畫面確認分別完成。此階段通過才稱「長期網站製作流程已驗證」。

## P8：app 與實機

平台、最低裝置、離線需求及發行方式目前未定。P8 開始前取得這些答案；不阻塞 P0–P7，不預設 iOS、Android 或封裝技術已決定。

1. 比較在選定平台承載現有 WebGL 場景的最小方案，做單場景實機 spike，再選 host；保留 P4 場景契約。
2. 實作前後景切換／恢復、音訊啟動、觸控、安全區、資產快取／離線更新與錯誤恢復。
3. 在指定最低裝置訂定並量測 FPS／frame interval、記憶體、啟動時間、發熱／長時間穩定；不拿桌面 browser 代替。
4. 完成所有正式房間的實機矩陣與安裝包；記錄版本、裝置、OS、資產與回退方式。

**完成條件**：可安裝測試包及指定裝置驗收通過。簽章帳號、商店素材、隱私／授權與公開發行另按真實需求處理；未經授權不發布。缺裝置或帳號時如實列出未完成項。

## 每批交付與信任依據

每個批次在本頁追加狀態，證據細節連向 `exports/<review-id>/` 或相關場景頁：

| 欄位 | 必填內容 |
| --- | --- |
| 問題／範圍 | 哪些同步點或重做被消除；實際檔案與 consumer |
| 版本 | 基準、變更 commit（未提交明記）、資產／設定版本 |
| 證據 | 命令結果、真產物、固定畫面、資源／效能比較；無法跑的項目 |
| 確認 | 技術通過、browser、使用者認可、實機與發布各自狀態 |
| 回退 | 可操作的版本／配對資產及不可逆事項 |
| 下一步 | 未完成項、依賴與下一個有界批次 |

主 agent 負責責任拆分、整合、美術比較與最終判定；Luna 可做獨立只讀盤點，Terra 可做指定 ownership 的實作／review；同檔不平行改，worker 不再委派。簡單或相依工作直接完成。

執行以本地可逆工作持續推進；主觀畫面、P7 房間選擇及 P8 平台是必要使用者輸入，在依賴點再提出，不對每個小步驟反覆請示。分段提交僅納入本輪已核對內容；推送、merge、部署依當次授權處理。
