# 雪落海窗：從初版到使用者接受的回顧

## 結論與確認範圍

2026-09-10 使用者明確表示「現在的是符合我的標準的」，授權 commit。接受的是目前網站：冷色近窗角落、3D 海雪、微轉與較近視角、3 隻水母與 7 隻海天使。這不表示舊版圖片、Blender 快取、任意螢幕／時刻或完整物理模型也獲確認。初版問題以本輪截圖、歷史場景筆記和現存程式交叉整理；未保存逐次對照的變因不能宣稱單獨造成某種效果。

## 為何初版不符合

我一開始偏重「畫面包含窗、雪、海、水滴」的元素清單，沒有先驗收觀察者站位、室內占比與窗內外亮度關係。結果雖有細節，卻像正面展示一塊窗景；寬牆、平直窗簾、大窗台與模糊影像一起削弱了日常小角落的感覺。這是製作順序與驗收問題，不是使用者少給材質細節。

| 關鍵 | 初版／中途問題 | 採用的改善 | 下次注意 |
| --- | --- | --- | --- |
| 相機與畫面比例 | 正面面海、室內佔比過大，參考中的側向近距離關係流失 | 使用者用相機工具選 position／target；其後 FOV 52°、左右各 7.5° | 先選站位與裁切，再做細節；保存 viewport、時刻、elapsed |
| 光照層次 | 全域補光讓牆與窗簾均勻發亮，空間像樣板材質 | 冷天空窗洞光、少量雪面反射與弱室內 bounce | 判斷光路與相對亮度，不用整體曝光或黑漆代替遮蔽 |
| 外景深度 | 曾使用含水氣與海的平面圖，移動鏡頭缺少真實視差 | 程序海面／天空、獨立玻璃、小平台及厚度雪層 | 可轉鏡頭時，先確認哪些景物真正具有幾何 |
| 窗簾 | 單獨直布片，沒有拉到旁邊牆面的收攏關係 | 完整布幅聚褶延伸至牆側，只有微小位移 | 布從哪裡掛、收到哪裡、根部與垂墜要連續 |
| 平台與窗框 | 外平台太深、上框橫條進入畫面 | 縮短至 1.4 m，細框，窗頂移出觀看範圍 | 窗框只是邊界，平台提供近景深度而不成陽台主角 |
| 畫幅覆蓋 | 只顧單張直幅，寬畫面露出牆盡頭與上緣黑條 | 向畫外延伸牆／玻璃／框／窗台 | 驗收直幅、16:9、超寬與轉角極限；不可再以單張截圖通過 |
| 生物線條 | 觸鬚高對比等長排列像白色梳齒 | 透明度降低、長度錯落、相鄰 PBD guide | 用實際觀看尺寸看輪廓，近景拓撲通過不代表場景自然 |
| 生物編舞 | 姿態多向上，觀察時像同方向擺件 | 兩隻水母錯時緩慢朝觀察者方向轉身／靠近 | 留停頓、滑行與異步，小變化即可，不做全群追鏡頭 |

## 房間是黑的嗎？

不是把整間房間材質設成黑色。`Materials.ts` 灰泥 base color 為 `#c2c1bc` 搭配程序紋理，roughness .96；框是深灰 `#202527`。目前深色主要來自冷亮外景相對於低照度室內、表面朝向、布褶法線與有限補光。`index.ts` 正午天空窗光 .715、雪面反射代理 .164、Hemisphere .112，曝光 1.02；並非測得的 lux。

這是令人信服的美術光路近似。RectAreaLight／Hemisphere 不提供完整窗洞遮蔽與 GI，不能說牆之所以暗是完整物理解算結果。下次先查 albedo、光源方向／強度、曝光、法線與遮蔽責任，分別改一項；不要因這次成功就把其他房間也壓黑。

## 下一次製作與迭代順序

1. 先寫清觀察者站位、主角、前中遠景和室內占比，用簡材質確認構圖。
2. 確認空間連續：牆／窗／台／布的接合及窗外幾何，先檢查可轉範圍與不同畫幅。
3. 分開調窗外亮度與室內受光，固定曝光對照；無人工燈不等於沒有間接光。
4. 再加入玻璃水滴、薄霜與布木細節；裝飾細節不能遮掩站位或比例問題。
5. 加動態與生物，以正式視距及暫停畫面檢查尺寸、透明度、附肢和異步，不只看近看工具。
6. 每次記變因、理由、固定條件、使用者採用／拒絕；功能測試、browser、使用者認可及發布是四種不同證據。
7. 網站改動後，註明舊 Blender 快取是否落後；重建時從現行程式重採樣，不拿舊驗收充當新版證據。
