# 偏好與風格決策

## 2026-09-10：房間入口與控制介面

使用者確認記憶泡泡概念稿「應該 ok」並要求照此實作。適用全站觀賞介面，不改寫各房間已確認的構圖、材質或光照基準。

- 開站先讓場景存在，再以漂浮、低彩度的記憶泡泡選房；不做一般卡片牆或儀表板首頁。
- 未指定房間的真正初訪可隨機提供一景；回訪保留上次房間，直接連結維持指定場景。
- 音樂播放獨立於設定面板；時刻與光束直接留在低存在感控制列，其他選項收進較小面板。
- 主要時刻控制直接顯示「晨曦、正午、暮色、月夜」四段；目前時段用白色粗體，其餘保持可讀的灰色。連續小時滑桿保留在設定面板作精細調整。
- 整體控制列更透明、更小，休息時降低存在感；鍵盤焦點與 reduced-motion 仍需可用。
- 房間名稱需比前版更大；泡泡以緩慢、非週期感的漂移呈現，並隨移動／接觸做輕微形變與薄膜光色變化。這是參考流場、阻尼、面積近似守恆與薄膜干涉的即時 UI 美術近似，不宣稱完整流體或光學模擬。
- 後續回饋指出前版漂移不明顯且略不自然：非主角房名再放大，方向改變需平滑；桌面滑鼠靠近可形成柔和排斥與短暫推流，但游標進入按鈕後應增加阻尼，優先保持可點擊性。此方向已實作待使用者看畫面確認。
- 最新截圖回饋要求泡泡房名與左側文案維持同一套視覺比例：泡泡大小仍可分主次，但不可讓整體縮放把非主角文字縮成另一個字級系統；主角房名不另加粗，以尺寸與光圈區分層級。此方向已實作待使用者看畫面確認。
- 針對主場景四角失衡與左下資訊被控制列遮住的回饋，採用「安靜的觀景儀表」：左上只放場景身份、左下只放當下狀態、右下收納操作；寬桌面用單列，中型桌面改為右側雙列，手機維持全寬雙列。字體收斂為展示襯線與操作無襯線兩組，象牙白只給目前選取與狀態刻度，滑桿平時降低對比。使用者於 2026-09-11 確認目前整體可保留，並要求 idle 時底部控制列與其餘 chrome 一起完全淡出；滑鼠或鍵盤再次操作時恢復。此確認不代表已發布。
- 泡泡目前以 CSS 氛圍呈現；若未來加入縮圖，只能使用真實場景輸出，不以概念圖冒充已完成畫面。
- 入口改採兩幕式：首次 landing 只顯示左側「留在這裡／想去其他房間」，不預先露出泡泡；使用者主動選擇其他房間後，泡泡才由畫面下方分批浮上定位。房內控制列的「其他房間」直接進入相同上浮選房狀態，不重播 landing。
- 所有房間泡泡維持同一尺寸並整體縮小約 15%；目前房間不再放大或放大文字，改用克制的暖黃色內光辨識，其他文字比例保持一致。此為 2026-09-11 的新候選，已實作待使用者看畫面確認。
- 使用者後續明確否決 1.42 秒、帶終點回彈的泡泡入場，並認為單純放慢到 4.2–4.65 秒的 CSS keyframe 仍像預設動畫。該方案保留為拒絕紀錄，不再採用。
- 2026-09-11 使用者要求先查浮升公式再實作：進場改由 `RoomBubbleMotion.ts` 統一管理。上升段以淨浮力與二次阻力的 UI 等效式 `dv/dt = a(1-(v/vt)^2)` 漸近終端速度；接近錨點後使用臨界阻尼 `e''+2ωe'+ω²e=0` 無回彈收束，再銜接既有 curl field 與 pointer 推流。首版把所有泡泡中心放在畫面高度約 114%、從靜止起步並加入最長約 1.1 秒的分批等待，使用者明確回饋為「在畫面下方好一陣子」且不自然，因此列為拒絕參數。現候選改為左側文案 0.58 秒直接淡入，每顆泡泡從自身錨點下方約 10–37% 畫面高度、帶 42% 終端速度的初始升力出發；等待中的泡泡保持透明，不再於同一條下緣先顯形或堆成一排，並以 45ms 基礎錯開加 session-seeded 0–60ms 延遲開始上升。形變跟隨速度並在上升時橫向展寬，進場不另播週期呼吸。這是研究啟發的介面美術近似，不是流體求解；已實作待使用者看動態確認。

## 下次製作先遵循（2026-09-09 本輪沉澱）

來源：使用者本輪隧道製作、回退、光影與動作回饋，以及「下次不會再講一次」的明確要求。以下為已表達的工作偏好；場景限定選擇見[隧道目前基準](../scenes/seaward.md#目前狀態)。不代表所有場景已重新驗收。

- **先沿用，再改動。** 開始先確認既有模型、套件、波場與動作是否可用。說明究竟共用哪個模組；「共享海波公式」不可說成「整套海洋系統已沿用」。
- **不確定喜不喜歡，就做可回退實驗。** 先保存當前基準 commit，再改；記錄試驗與基準的對應。回到上一版時保留候選；只要求加回幾項時，只恢復指定項目，不把已拒絕的整套效果帶回來。
- **依圖片理解站位與空間。** 檢查可轉動視角、畫面邊缘和牆地接合，而非只比對單張預設角度。隧道採靠右牆站定、向左觀看；這個座標不是所有房間的通用設定。
- **整體要持續有生命感。** 使用者原意是「像循環動畫一樣，都有些東西在動」：水、波光、草、生物保持細微流動。不要解讀成所有物件同頻擺動，也不要把多頻程序動畫宣稱為固定秒數無縫影片。
- **草要像受到風作用。** 微風至小風為主，偶爾較強陣風；形變要有柔軟度與延遲，根部穩定。此為本輪自然動態方向，非已測得的風速或植物物理模型；其他場景按原基準適配，不自動重調。
- **動作先講得通，再防穿透。** 柔鰭不能像硬支架把身體頂起。隧道魟魚需先升空、再翻一圈、回平保持、最後下降；避免用最低鰭尖逐幀抬高整隻身體造成「撐竿跳」。完整動作與變形後幾何都要檢查。
- **光影要有共同原因。** 改時刻應一起影響光向、強弱、色溫與光斑；不接受固定牆面紋理被獨立亮度遮罩揭開的感覺。觀察切換過程，不只看起點與終點。共用順向2秒規則見下節；目前仍為美術光路近似。
- **先做小而可辨識的改動。** 真實感不是一次增加所有風化、濕度、反射、草形與生物擺動。保留已確認構圖，按回饋分項試驗；採用與拒絕都留紀錄。

驗收習慣：固定鏡頭與動畫時間比較，另檢查動態、跨午夜、途中重選及暫停下切時刻。測試通過、browser看到、使用者認可、PR合併與正式部署分別記錄；尚未確認的主觀效果不寫成已接受。新增規則直接沿用，不要求使用者重述。

## 2026-09-09：共用時刻切換規則

使用者明確要求全場景時刻只向前循環：晨曦 → 正午 → 暮色 → 月夜 → 晨曦。每相鄰預設時段2秒，跨兩段4秒、三段6秒；不使用最短路徑倒轉。任意小時按相鄰時段比例分配時間；切換中重選從當前顯示時刻接續。時刻驅動整組受光參數，不能分別淡入終點亮度／光向。適用共用播放器手動按鈕與滑桿；本地即時時鐘、房間載入與固定時刻試片維持各自模式。來源：本輪使用者對洞口波光突兀的回饋。
