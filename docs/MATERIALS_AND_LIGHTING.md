# 材質與光照製作筆記

2026-09-07：依使用者要求，這是持續新增場景、替換樹種時的共同筆記入口。每次相關製作都更新，不只在完工時補一段摘要。這是專案工作流程，不是背景排程。

## 文件分工

- 本文：跨場景共通原則、記錄格式與檢查方式。
- `docs/scenes/<scene-id>.md`：該場景的材質、參數、近似方式與驗收紀錄；同場景的樹種變體記在該頁，長大後再拆出有連結的獨立筆記。
- `.claude/memory/blender-production.md`：Blender 製作歷史與接手點，保留歷史，不當作當前參數清單。
- 程式／Blender 來源腳本：可執行參數的權威；文件記錄「為何這樣做」、單位和對應版本。發現不同步時先核對程式，不照舊文件覆盖效果。

目前已確認基準：[樹影午後](scenes/leaflight.md)。新場景可沿用光照思路，但不能直接複製曝光、光強、霧密度與樹葉參數後宣稱適用。

## 共通判斷原則

1. **先確認光從哪裡來。** 記錄天空、日／月光、地面與牆面反射。畫面中的光源與用來近似它的 renderer light 分開說明。
2. **材質和照明分開調。** base color 不含畫死的日照；記錄 roughness、metalness、normal、opacity／alpha test，以及哪些項目尚未實作。不要用 emissive 掩蓋一般物體的暗部問題。
3. **直射和間接光不重複。** 烘焙貼圖需註明是否包含 direct、indirect、albedo，並記錄 UV、色彩空間、強度換算與翻轉方向。
4. **暗部保留體積。** 補光考慮受光方向、可見開口與距離。均勻加亮會使魚、枝葉和牆面失去形體；真正缺光的位置可以暗下來。
5. **先定義介質。** 窗洞是開放空氣、玻璃或水面，必須明確。開放窗洞不能靠反光／霧膜營造深度；玻璃、透光葉片和水面則各自記錄其傳輸模型。
6. **動態與陰影同步。** 葉片、魚身變形與 shadow pass 使用一致的時間和幾何；暫停後受光位置不可繼續漂移。
7. **如實標示近似。** PBR 材質不代表完整物理模擬；程序擺動、單點反射、shadow map、烘焙 GI、流體求解各自列出，不混稱「真實物理」。

## 換樹種時的必填項目

| 項目 | 要記錄什麼 |
|---|---|
| 身份／依據 | 樹種名稱、參考來源與資產授權；未核實時標為造型近似，不填虛構物種數據 |
| 幾何 | 葉形、大小範圍與單位、排列、冠層疏密、枝條粗細與連接方式 |
| 材質 | 葉面／葉背色差、粗糙度、厚度或透光近似、枝幹材質；哪些值是美術調整 |
| 逆光與投影 | 葉片是否透光、陰影疏密與軟硬、alpha-cutout 邊緣品質 |
| 風 | 枝幹彎曲、葉柄與葉面擺動、振幅／速度／seed；程序動畫或物理解算 |
| 接入影響 | 是否重烘焙間接光、重設陰影範圍、改變窗洞遮蔽或曝光；不能假定換 GLB 即完成 |
| 驗收 | 同鏡頭、時刻、曝光與風相位對照，記錄差異與使用者確認範圍 |

不要預設所有樹種共用同一片葉、同一擺動頻率或同一逆光色。沒有植物形態資料時，可以先做明確標註的美術草稿，再補證據。

## 每個場景／變體的筆記格式

```markdown
## 場景或變體名稱
- 日期、分支、commit、狀態：草稿／已實作待看圖／使用者已確認。
- 美術目標：構圖、亮暗關係、介質、保留與避免的效果。
- 模型／材質來源：.blend、產生腳本、GLB、貼圖、來源與授權。
- 光路：直接光、天空、反射、體積散射；各自的實作與限制。
- 參數：名稱、值／單位、檔案／符號、物理量或美術值、調整理由。
- 動態：變形、路徑、影子同步、暫停、重現 seed／時間。
- Blender → 網站：保留／烘焙／重建／未支援的項目。
- 驗收：固定鏡頭、viewport、時刻、曝光、動畫時間與品質；證據及尚未驗證項目。
- 修改紀錄：問題 → 原因 → 改法 → 結果 → 可退回 commit。
```

## 每次修改的收尾

更新相關場景筆記與程式一起 commit。檢查亮處／暗處、窗洞附近／深處、物體朝向、時段切換和暫停；範圍較小的改動只驗相關項目。保存可回看的基準版本，明確区分使用者確認、browser、build、實機與發布。需要圖像比較時，將輸出路徑與對應版本記進場景頁，不只留在聊天中。

## 共用元素與场景校準

現行入口見 [ARCHITECTURE.md](ARCHITECTURE.md)。相同的波場、折射公式、模型資源釋放與亂數序列可引用 `src/shared/`；曝光、天空、開口尺寸、材質參數、動態和各場景光照近似仍由 `src/places/<scene-id>/` 擁有。只有同樣的行為至少出現在兩處才抽共用；不要把可調參數一律變成全域預設。

新模型或樹種必須同時保留可編輯來源、網頁資產與已驗收狀態。當動畫程式與模型版本不匹配時，保留草稿並明示不可接入，不以fixture測試當作真實資產驗收。

## 2026-09-09：參數試片與正式設定

Afterlight 幾何權威在 `assets/config/afterlight-geometry.json`，runtime 與 Blender 同讀；製作室線框也使用相同 helper。修改開口會使舊 GLB／間接光失效，線框只是草稿邊界，不證明陰影已符合候選。

固定光方向與倍率可由 `afterlight-study.json` 試片／採用；直接光與散射仍沿用正式 Lighting，曝光由 renderer 處理。舊 GI 與 reflection capture 不因光方向滑桿自动重解；工具明确顯示限制。參數、資產 fingerprint 與採用／回退流程見 [製作室](production/STUDIO.md)。

像素驗收需固定「建構」亂數與 elapsed；只固定動畫時間無法重現使用 Math.random 建立的浮塵。測試可固定 constructor 的亂數，不因此改正式房間既有分布。
